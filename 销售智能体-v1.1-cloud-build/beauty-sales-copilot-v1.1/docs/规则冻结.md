# V1.1 规则冻结与实施缺口

## 已确定（沙盒可执行）
- 客户推荐关系：建档时单一直接推荐人绑定；不提供修改推荐人接口。
- 积分与充值人民币余额分别记账。充值余额单位“分”，奖励积分为整数。
- 一积分最多抵扣一元，单笔有效消费积分抵扣最多50%。
- 默认直接推荐人可获已完成合格净消费基数的5%整数积分；按履约触发；积分抵扣部分不得二次计奖。
- 上游间接推荐关系仅做分析，不发放间接消费返佣。
- 医疗美容项目的积分抵扣与推荐发奖默认拒绝。
- 订单锁定规则版本；重复提交不得重复扣账或发积分。
- 退款恢复原支付结构。若推荐奖励已被使用，则退款转人工处理（V1.1仍需实现争议/补偿子系统）。

## 明确非生产范围 / 上线阻断项
1. 真实支付渠道（微信/支付宝）未接入，当前 checkout-demo 将外部支付视为“模拟已支付”；topup-demo 同理。
2. 当前使用单个开发 API Key，无正式登录、RBAC、租户隔离、密钥轮换和客户信息授权。
3. 仅完整履约、全额退款；部分退款、分次疗程、跨店清算、营销预算和人工冲正流程尚未实现。
4. SQLite 并发与本例增减余额逻辑不支持真实资金高并发；生产需使用 PostgreSQL 行锁、唯一业务事件和正式双分录账务设计。
5. 无第三方收付款对账、不可篡改审计、监管报表和财税核算。
6. Android 当前仅可编译的导航页面工程；未实现网络认证、语音识别、知识库或实时 AI。
7. 推荐奖励与医美营销在真实经营主体所在地需要法律、财税和广告专项审核。

以上任一阻断项未完成，不得对公众部署或处理真实资金。
